# 领域文档规则

## 探索前需要读取的文档

- 根目录的 `CONTEXT.md`；或
- 根目录的 `CONTEXT-MAP.md`（如果存在），以及其中指向的相关上下文 `CONTEXT.md`；
- 与当前工作区域相关的 `docs/adr/` 中的 ADR。

如果这些文件不存在，静默继续，不需要提前创建。`/domain-modeling` 会在领域术语或决策真正需要记录时再创建它们。

## 目录布局

本仓库使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── app/
```

## 术语规则

在 issue 标题、重构建议、假设和测试名称中使用 `CONTEXT.md` 定义的领域术语。不要擅自引入 glossary 明确避免的同义词。

如果需要的概念尚未出现在 glossary 中，应先判断是否真的需要新术语；确认是领域缺口时，交给 `/domain-modeling` 处理。

## ADR 冲突

如果输出与现有 ADR 冲突，必须明确指出冲突，而不是静默覆盖。例如：

> 与 ADR-0007 冲突，但由于……，建议重新评估该决策。
